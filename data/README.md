# data/ — inputs and their provenance

Layout:

| dir | contents | in git? |
|-----|----------|---------|
| `data/raw/` | immutable inputs (concept table, semantic-key source, pole labels) | yes (small) |
| `data/interim/` | pipeline checkpoints (canonical CSV, IPA, `<Lang>V.txt`, QC flags) | no (gitignored) |
| `data/processed/` | phonetic/semantic embeddings (`<Lang>Emb.txt`, `SemanticsEmb.txt`) | no (gitignored) |

### Do NOT use `nguasach.csv` (repo root)

That file is a corrupted export: Greek/Russian/Chinese/Japanese are mojibake and
Korean/Thai/Arabic/Hebrew/Hindi were replaced with literal `?`. The pipeline
regenerates a UTF-8 CSV from `raw/nguasach.xlsx` (`nguasach run data`) and asserts
integrity (`tests/test_canonical_csv_integrity.py`).

## Phonetic-similarity-vectors data (not vendored)

`third_party/phonetic-similarity-vectors/` contains only the **code** + feature
tables. The multi-GB `<Lang>Emb.txt` / `<Lang>V.txt` / `UniEmb.txt` (~3.2 GB) that
lived alongside it in the original working copy
(`E:\Project\Work in Progress\phonetic-similarity-vectors-master`) are **stale**
(built from the old 26k corpus) and are regenerated by `nguasach run phonetics`
into `data/processed/`.
